CMX 长上下文流量需求

给定模型布局、可复用前缀和 用户提供 的有效 Prefill 吞吐，计算 PD 分离下需要从 CMX 读取、写入多少数据。这里输出的是 offered load，不是 CMX 实测性能。

分析模型，不是 benchmark，也不是 NVIDIA/VAST sizing 工具。公开材料没有给出可复现的 CMX 持续带宽、延迟或队列模型；因此默认不设带宽上限。只有填写“链路预算”后，页面才计算该假设下的上限。

口径

        
    
          
  • C 是请求到来前的既有上下文；E 是本轮新增 token；最终长度为 C+E。
    • 
          
  • 命中 token 按块向下取整。q 把“前缀命中”和“确实从 CMX 远程读取”分开。
    • 
          
  • a 是写入 CMX 的新状态比例；它不是 gateway 准入率。
    • 
          
  • V4 的 128-token SWA 页与 FP32 compressor residual、K3 的 KDA 状态按每会话计；是否写最终续算状态可关闭。
    • 
          
  • V4-Pro 的 9.62 GiB 是 BF16 paged KV（含 SWA）锚点；可移交会话总量还要加 17.84 MiB compressor residual。
    • 
          
  • 布局包含逻辑公式、引擎页和 payload 估算三类，不能互相冒充。CMX 最终序列化契约尚未公开。
