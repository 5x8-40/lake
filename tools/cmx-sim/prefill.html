Vera Rubin × CMX · PD 分离 Prefill 跑满

负载：每人一条约 1M token 会话，前缀命中可调。工作点是 Prefill 池 GPU 算力打满，不是 Decode 每步用 HBM 扫完整 KV。 高命中时 Prefill 几乎不产新 KV，但要把前缀从 CMX 预取到 Prefill GPU 才能 attend——读远大于写。

V4-Pro 在 1,048,576 token、BF16 下是 9.62 GiB（vLLM 附录：30×c4a + 31×c128a，共享 KV 1024 B/entry）。 先前用「论文 10% of V3.2」或「平均 5.2 KB/token」会得到 ~5 GiB，那是错的。

假设与口径

        
    
          
  • PD 分离：Prefill GPU 只做 unique token 的前向。前缀 KV 从 CMX 预取到 Prefill HBM（NIXL prestaging 这条路径）。
    • 
          
  • 跑满 = unique_tok/s = (peak_FLOPS × util) / FLOPs_per_unique_token(C)。默认 Rubin NVFP4 50 PFLOPS、util 40%，两者都可改。
    • 
          
  • 写 CMX = 新 KV（unique × 增量字节）。读 CMX = 每个请求把命中前缀拉到 Prefill。99% @ 1M 时读/写 ≈ 99。
    • 
          
  • dtype 是独立选项：切模型不会改精度。V4 附录 9.62 GiB 用 BF16；GLM/K3 的 1M serving 常用 FP8。GLM 还可选逻辑 576 B/层或 vLLM fp8_ds_mla 656 B/层。
    • 
          
  • V4 体积用压缩后的 entry 数，不是 SGLang DeepSeekV4SingleKVPool.get_bytes_per_token 的 584 B 未压缩页布局。
    • 
          
  • 没有对照 lake / Mooncake / 其它集群。数字只描述这条 Prefill→CMX 管道。
    •
