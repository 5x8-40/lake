# SLO — 服务等级目标

给用户的可量化质量承诺。SLO 是架构硬约束:倒逼 Prefill/Decode 分离、KV 传输、分层缓存等设计在预算内完成。

> 目标值为初版草案,待 P7 校准。

---

## 延迟

| 指标 | 定义 | 目标（draft） | 约束的设计点 |
|------|------|---------------|--------------|
| TTFT | 请求发出 → 首个 token 返回 | P50 < 400ms, P99 < 800ms | 前缀命中率、prefill 计算量、KV 传输、**执行模式选择** |
| TTFT (D-direct 路径) | 本地命中直跳的 TTFT | P50 < 150ms | 本地命中率、存储池 HBM 放置本地性 |
| ITL | 逐 token 间隔 | P50 < 50ms, P99 < 200ms | decode batch 调度、KV 本地性、投机解码 |
| 队列等待 | 入队 → 开始执行 | P99 < 300ms | 各池容量、弹性扩容时延 |

> TTFT 按主流路径(PD 分离/混部)设;D-direct 是本地命中(前缀 KV 已在执行节点 HBM)的快路径,给更紧目标。模式选择开销须 < 5ms,否则吃掉本地命中省传输的收益。

## SLO 预算与过载控制

- 每项 SLO 设**错误预算**（如可用性 99.9% → 月预算 ~43min）。
- **过载控制（限并发 / 拒请求 / 按优先级丢弃）归 gateway / 外部控制面**，不在推理系统内执行。推理系统只管执行：忠实执行被分配的请求，对过载的响应是"上报队列与资源指标"供 gateway 决策，而非自行降 batch / 拒请求。
- 推理系统侧的职责边界：Worker 不得为保 SLO 自行降低 batch size 或丢弃请求；队列与 in-flight 指标实时上报 gateway，由 gateway 做入口准入与过载 shedding（限并发/拒请求/按优先级丢弃），已准入请求的 SLO 路由与优先级排队由 Router 负责（不丢请求）。
- 可用性 SLO（99.9%）针对**非过载、已准入**的请求；过载导致的拒绝不计入推理系统的失败率，由 gateway 的过载策略负责。

## P7 校准结论（P7.1–P7.4，mock/原型环境）

每条 P0 假设的量化结论：**成立 / 条件成立 / 待真机**。测量入口：`bash scripts/bench.sh` + `cargo run -p lake-tiered-store --bin p73_curves` + `python3 bench/cost_model.py`。

| P0 假设 | 结论 | 量化依据 | 条件/边界 |
|---------|------|----------|-----------|
| KV 命中率 >60%（公共前缀） | **条件成立** | zipf+70% 共享下 L0=512 块（≈64K token/节点）达 64.3%；L0=128 块仅 52.6% | 容量足够时成立；容量不足显著劣化（P7.3 hit_curve）。口径：miss 含 L3 命中（L3 fetch 慢视同 miss）；若 L3 计命中，cap512 总命中 66.3% |
| GC/碎片整理 <10% 带宽 | **成立**（后台口径，构造保证） | `BandwidthPool::default_throttle` 构造保证（10% 链路/1s 窗，可暂停）——非测量值 | 只含后台 GC/整理；数据路径同步迁移放大（容量不足时 moved/(r+w)≈150%，L3 计入读）另计——churn 抑制是开放问题（issue #68） |
| 扩容决策→Ready <10s | **条件成立**（mock 参数下） | 扫描 12 组最差 1.65s（选定 sleep 的算术结果，非硬件校准）；预算分配 provision ≤5s + gate ≤2.5s + 余量为**外推草案** | 真机单层加载成本待校准（TODO-P7-hw）；Ready=serve gate 语义 |
| D-direct 模式选择开销 <5ms | **成立** | 纯内存读镜像，µs 级（P6.3）；P7.2 确认必须性（首块传输收益 3.5ms 同量级） | 镜像零-RPC 路径；miss 回退权威的一次 RPC 不在此预算 |
| 模式选择阈值（传 vs 算） | **成立**（v1） | 分界带宽 ≈0.57 GB/s；≥1 GB/s 时「≥1 块命中即传」恒成立 | <0.5 GB/s 重算恒胜；sub-GB/s 细分待真机 |
| block=128 粒度 | **成立** | 有效复用率 94.6%（64:97.3% / 256:89.2%） | 维持默认；真 workload 碎片率 P7.3 已复核 |
| 写回频率 N | **已校准** | 字节量与 N 无关，ops ∝ 1/N → 建议 N=2–4 块/批 | 按 ops/RPC 预算调整 |
| promote cost hops 模型 | **方向成立，L3 欠估** | hops=3（L3 源）较 hops=1 超线性 **4–10×**（跨运行漂移；mock 内存层 hops1≈hops2 不可区分，绝对 µs 不可复现——只取比值口径，review #65） | 建议 hops≥3 加固定惩罚 / L3→L0 走批量异步（决策见 issue #68） |
| TTFT P50<400ms（PD 分离） | **部分成立** | KV 传输占比 ≈2%（2048 token 全命中传 7.9ms），瓶颈在 prefill 计算 | prefill 计算绝对值待真机；传输不构成瓶颈 |
| 本地命中率 >40%（重复请求） | **条件成立**（原型口径，亲和选路**已含于本 PR**（原 #69）） | 亲和两段式（B1）2/4 节点 = 1.000/0.905；RR 基线 0.230/0.106 不达标；放置单边（RR+B2）4 节点 0.333 仍不达——亲和是主因，B2 是收敛加速与兜底（P7.6，#69；连续本地前缀口径复测） | bench_p76 本地命中率**已升级为 CI 回归门禁**（确定性元数据口径，亲和各配置断言 ≥40%；X5 收口）；mock 绝对时延/吞吐仍为 `t.Log` **测量值、非断言门禁**；元数据口径，真机 HBM 容量/驱逐压力未建模（TODO-P7-hw） |
